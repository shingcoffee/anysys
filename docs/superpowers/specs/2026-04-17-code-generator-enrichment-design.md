# Code Generator Enrichment — Design

**Date:** 2026-04-17
**Scope:** All 116 generators under `app/services/code_generators/element_types/`
**Depth:** Enrich `generate_body` to cover every configuration case (correctness + richness), plus matching `validate_config`, rspec tests, and JS `configSchema` entries.

---

## 1. Problem Statement

The Anysys has 116 code generators spanning 14 element categories. An audit (summarized in §3) reveals three systemic issues:

1. **Generated code is brittle.** Nil/blank values in `ctx` crash generated steps; HTTP, DB, parse, and file operations fail silently or raise uncaught exceptions; several generators contain outright bugs (e.g., `rate_limiter_generator` off-by-one, `render_response_generator` flash syntax, `retry_with_backoff_generator` dead `break`).
2. **Many documented configuration branches are not implemented.** `validate_config` or `sample_input` hints at modes that `generate_body` never reaches (e.g., `approval_gate`'s `majority` mode, `notify`'s Slack/SMS channels, `parse_data`'s error branch).
3. **Property-editor UX is stunted.** 80 of 116 generators have `configSchema: []` in their JS action definitions. Users cannot structure these generators through the UI at all — they rely on freeform text.

**Goal of this project:** For every generator, `generate_body` handles every realistic configuration case for its domain; `validate_config` rejects every malformed case; the UI `configSchema` exposes every field; and rspec covers every branch.

---

## 2. Goals & Non-Goals

### Goals

- Correctness: generated Ruby is nil-safe, handles empty collections, and rescues known failure modes of the operation it wraps.
- Config coverage: every config branch acknowledged by `validate_config` has an implementation in `generate_body`.
- Richness: each generator supports the feature set expected of its category's real-world analogue (see §5 rubric).
- Consistent error contract: `ctx[:_last_error]` populated on rescue; `errorStrategy` config field drives fail behavior.
- UI parity: every generator's `configSchema` reflects the full set of fields its Ruby reads.
- Test coverage: every branch generated by `generate_body` is covered by at least one rspec example.

### Non-Goals

- Rewriting existing ViewComponents. The property-editor UI is schema-driven (`buildStepConfigFieldsHTML`); adding a config field means appending to a `configSchema` array in `app/javascript/flowchart/constants/action_configs/*.js` — these JS edits are **in scope**; new Ruby/ERB components are not.
- Refactoring `SourceAssembler`, `CodeIntrospector`, `GeneratorRegistry`, `GeneratorValidator`, `MetadataDSL`, `TestRunner`. Infrastructure stays put.
- Creating new element types. Only enriching the 116 existing generators.
- Adding new icons / visual design.
- Page-builder features (`app/components/page_builder/`).
- Backwards-compatibility shims for renamed config keys. Per AGENTS.md, treat this as a brand-new application — we pick the best name and change all three layers.

## 4. Architecture

### 4.1 Three-Layer Contract (tightened)

```
┌──────────────────────────────────────────────────────────┐
│ JS configSchema                                           │
│ app/javascript/flowchart/constants/action_configs/*.js    │
│ (Fields: key, type, label, required, default, options,    │
│  placeholder, visibleWhen)                                │
└────────────────────────────┬─────────────────────────────┘
                             │  element.config / element.properties
                             ▼
┌──────────────────────────────────────────────────────────┐
│ Ruby validate_config(cfg) → errors[]                      │
│ Rejects: missing required; unknown enum value; malformed  │
│ combinations; stale key names                             │
└────────────────────────────┬─────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────┐
│ Ruby generate_body → Ruby source string                   │
│ Every value accepted by validate_config has a branch;     │
│ every branch is nil-safe; every risky op is rescue-wrapped│
└────────────────────────────┬─────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────┐
│ rspec                                                     │
│ One case per accepted config branch + invalid-config case │
│ + shared example "covers all configured branches"          │
└──────────────────────────────────────────────────────────┘
```

**Invariant:** The set of config keys declared in `configSchema`, referenced by `validate_config`, read by `generate_body`, and covered by rspec **must agree**. Discrepancies are caught by the new shared example.

### 4.2 Cross-Cutting Enrichment Rules

These rules apply uniformly before any category-specific richness.

**R1 — Nil-safe ctx reads.**
When generated code reads a ctx value that it then iterates, indexes, or dereferences, it must be guarded. Introduce a helper module `CodeGenerators::Shared::CtxReader` with methods:

```ruby
# In ctx_reader.rb
def safe_read(ctx_var, type: :any)
  case type
  when :array then "(ctx[:#{ctx_var}] || [])"
  when :hash  then "(ctx[:#{ctx_var}] || {})"
  when :string then "ctx[:#{ctx_var}].to_s"
  else             "ctx[:#{ctx_var}]"
  end
end
```

Every collection-consuming generator (map/filter/sort/group/partition/chunk/etc.) uses `safe_read(var, type: :array)`. Every hash-consuming generator uses `type: :hash`.

**R2 — Standard error contract.**
All generators that wrap an operation which can raise at runtime (HTTP call, DB query, parse, file op, crypto op, external gem) gain a new config field `errorStrategy` with values:

- `continue` (default) — rescue and set `ctx[:_last_error]`, return `true`
- `fail_track` — rescue, set `ctx[:_last_error]`, return `false` (Railway fail track)
- `raise` — let the exception propagate

Generated code pattern:

```ruby
begin
  # risky op here; writes ctx[:<resultVar>] on success
  true
rescue => e
  ctx[:_last_error] = { source: "<generator_name>", message: e.message, class: e.class.name, at: Time.current }
  <behavior per errorStrategy>
end
```

Introduce `Shared::ErrorWrapper` module to emit this block consistently.

**R3 — Timeout for blocking ops.**
Generators performing blocking I/O accept a `timeoutSeconds` config field with a sensible per-category default (HTTP=30, DB=60, signal_wait=existing, file=120, AI=60). The existing `BaseGenerator#wrap_with_timeout` already exists — extend it so every applicable generator opts-in via metadata (`generator_metadata { supports_timeout default: 30 }`).

**R4 — Shared-helper adoption.**
- Every HTTP-making generator uses `Shared::HttpRequestBuilder`. No inline `Net::HTTP` duplication.
- Every condition-evaluating generator (`if/while/case`) uses `Shared::ConditionBuilder`.
- Every ctx-reference operand (`"ctx.foo.bar"` → `ctx.dig(:foo, :bar)`) uses `Shared::OperandConverter`.

**R5 — Output contract standardization.**
Standardize the variable-naming convention across all generators:
- Result output: **`resultVar`** (single-value result written to `ctx[:<resultVar>]`)
- Source collection: **`sourceVariable`**
- Target collection: **`targetVariable`**
- Iteration item: **`itemVariable`**
- Iteration index: **`indexVariable`**

Existing inconsistencies (e.g., `outputKey`, `targetVar`, `target`, `resultVariable`) are renamed to the canonical form in all three layers — per project rule "Do NOT take backward compatibility into consideration".

**R6 — Config branch coverage.**
A new shared example:

```ruby
RSpec.shared_examples "covers all configured branches" do |generator_class|
  it "generates non-stub code for every enum branch in configSchema" do
    schema = GeneratorSchemaReader.read(generator_class)
    schema.each_enum_field do |field, value|
      element = base_element.deep_merge("config" => { field => value })
      generated = generator_class.new(element, {}).generate_body
      expect(generated).not_to match(/\A\s*#.*\n\s*true\s*\z/)  # reject stub output
    end
  end
end
```

This catches the case where `validate_config` accepts a value but `generate_body` has no branch.

### 4.3 New Shared Modules

Located under `app/services/code_generators/shared/`:

- **`ctx_reader.rb`** — nil-safe ctx access helpers (`safe_read`, `safe_dig`, `ensure_array_expr`, `ensure_hash_expr`).
- **`error_wrapper.rb`** — emits the standard `begin/rescue/_last_error` block with `errorStrategy` behavior switching.
- **`timeout_wrapper.rb`** — already partially in `BaseGenerator`; factored into a module with default-aware API.
- **`config_field_reader.rb`** — shared helpers for reading config with defaults (`fetch_with_default`, `fetch_enum`, `fetch_int_positive`).
- **`schema_reader.rb`** — reads the Ruby-mirror of `configSchema` (see §6.6) at spec time to drive the R6 shared example. The reader itself does not parse JS — it loads the generated `spec/support/config_schemas.rb` mirror.

### 4.4 Extension Points in `BaseGenerator`

```ruby
module CodeGenerators
  class BaseGenerator
    include GeneratorInterface
    include Shared::CtxReader
    include Shared::ErrorWrapper
    include Shared::ConfigFieldReader

    def generate_step_method
      body = generate_body
      return nil unless body
      step_name = derive_step_name
      <<~RUBY.chomp
        def #{step_name}(ctx, **)
        #{body.gsub(/^/, "  ")}
        end
      RUBY
    end

    # New hook: generators can override to declare they want automatic
    # error-wrapping rather than writing begin/rescue by hand.
    def wrap_with_error_strategy?(action_kind: nil)
      false  # opt-in; complex generators wrap manually
    end

    private

    def apply_wrappers(code)
      code = wrap_with_error_strategy(code) if wrap_with_error_strategy?
      code = wrap_with_timeout(code)
      code = wrap_with_retry(code)
      wrap_with_guard(code)
    end
  end
end
```

### 4.5 JS configSchema Extension

Each `action_configs/*.js` file contains objects like:

```js
{
  value: "cache_write",
  label: "Cache Write",
  ...
  configSchema: [ /* field objects */ ]
}
```

Field objects support these keys today: `key`, `type`, `label`, `required`, `default`, `placeholder`, `options` (for select), `visibleWhen`. We do not introduce new schema shapes — we populate the existing shape. If a generator needs a new field type (e.g., `condition_builder` for rich condition editing), we reuse the existing `condition_builder_component` reference pattern documented in the property-editor property popup code.

### 4.6 Namespace Consolidation

No module or file renaming. The existing `element_types/<category>/<subcategory>/<name>_generator.rb` structure stays. Only file-internal changes.

## 5. Per-Category Parity Rubric

For each category, define the reference API/standard that generators in that category should match, plus the minimum feature set every generator gets.

### 5.1 flow_control (14 generators)

Target: Native Ruby control flow + Trailblazer Railway semantics.

Every generator in this category:
- Reads ctx with nil-safety (R1)
- Uses `ConditionBuilder` for any user-facing condition (R4)
- No infinite loops without a hard bound
- Documents which ctx keys it writes

Specific:
- `decision`: already rich; only verify nil-safety on operands.
- `switch`: validate that `else_branch_index == cases.size` invariant holds; make fallback index configurable.
- `loop`: for_each needs `ensure_array_expr`; do_while/while need explicit `break` on max-iteration.
- `timer`: condition_wait needs a hard `timeoutSeconds` bound (not infinite loop).
- `signal_wait`: already rich; verify payload schema check.
- `saga`: don't swallow compensation errors silently — log and aggregate.
- `transaction`: add `timeoutSeconds`; validate isolation level per-adapter.
- `parallel_for_each`: deep-dup ctx snapshot; thread-safe result collection; surface per-thread errors via `ctx[:_thread_errors]`.
- `error_handler`: route by error class (pattern match on `e.class.name`); not just `errorTypes` string.
- `end`: support `http_response` with status + headers; support file/streaming response bodies (generate the common case).
- `fork` / `join`: stay pass-through; ensure `joinStrategy` validates against enum.
- `start` / `subflow`: untouched (nil `generate_body`).

### 5.2 process/data_operations (31 generators)

Target: Rails `Array` / `Hash` / `String` semantics + common dig/merge idioms.

Every generator in this category:
- Supports **nested path** field references (`"user.profile.name"` → `dig(:user, :profile, :name)` via `OperandConverter`).
- Accepts **string or symbol keys** on the collection (use `with_indifferent_access` or both-key probe).
- Short-circuits on empty collection with an explicit output (`[]`, `{}`, `nil`).
- Uses `ensure_array_expr` / `ensure_hash_expr` from R1.

Specific highlights:
- `map_collection`, `filter_collection`, `sort_collection`, `group_collection`, `partition_collection`, `find_in_collection`, `uniq_collection`, `any_all_none_check`, `pluck_fields` — add nested path support; add multi-field variant (sort/group by multiple keys).
- `reduce_collection` — custom expression gets `|acc, item, idx|` signature.
- `regex_extract` — validate regex at generate time by compiling a `Regexp`.
- `format_string` — support `{{path.to.field}}` resolution via `OperandConverter`.
- `parse_data` — JSON/CSV/XML/YAML branches; rescue on parse failure with R2.
- `serialize_data` — XML needs validated root element; CSV supports nested via dot-notation.
- `calculate` — empty-collection guard for `avg`; null-filter option.
- `hash_manipulate` — nested path support for `pick`/`omit`.
- `string_manipulate` — escape regex for `gsub`; Unicode-safe case ops.
- `type_cast` — boolean uses `ActiveModel::Type::Boolean` (documented); date parse accepts `in_time_zone`.
- `transform` — drop reference to undefined `element` variable; align with `map_collection`.
- `merge_data` — validate both sides are hashes.
- `math_operation` — NaN/Infinity policy for div-by-zero per config.
- `log` — per-call customizable context; validate log level.

### 5.3 process/model_operations (17 generators)

Target: `ActiveRecord::Relation` API + Rails conventions.

Every generator in this category:
- Scopes every query by `customer_id` (multi-tenant). Enforced in both `validate_config` and codegen.
- Routes conditions through `Shared::ConditionBuilder` (same shape as `QueryBuilder.where`).
- Wraps bang-method calls (`find_by!`, `update!`, `save!`) with R2 error strategy.
- Uses `EntityEntry.build_for(ctx[:bound_entity])` consistently — never raw class names.

Specific:
- `query_models` — already rich; validate JOIN entity_ids exist at generate time via a comment-hint (can't actually check in codegen, so emit a runtime guard).
- `find_model` — `where` strategy renamed to `where_first` or `where_many` for clarity.
- `new_model`, `save_model`, `update_model`, `destroy_model`, `upsert_model`, `clone_model` — consistent customer_id scoping; attributes map through `OperandConverter` (not literal).
- `pluck_fields`, `count_records`, `check_existence`, `aggregate_query` — conditions via `ConditionBuilder`.
- `bulk_import` — implement true `upsert_all` branch; batch size config; unique_by config.
- `batch_operation` — each-branch with configurable body expression; update_all with mapped fields.
- `raw_sql_query` — reject SQL containing `#{`-style interpolation markers; use parameterized bindings via `ActiveRecord::Base.sanitize_sql_array`.
- `soft_delete_model` — configurable field name + value expression; default `deleted_at = Time.current`.
- `transition_state` — integrate with `AASM` / `state_machine` if gem present (detect via constant check in generated code).

### 5.4 process/communication (4 generators)

Target: `Net::HTTP` / `Mail` gem / ActionMailer parity.

- `api_call` — route through `HttpRequestBuilder`; add `timeoutSeconds`, `retryCount` (use `BaseGenerator#wrap_with_retry`), `responseFormat` (json/text/binary), 4xx/5xx branch.
- `send_webhook` — route through `HttpRequestBuilder`; HMAC signing; retry; dead-letter on exhaustion.
- `send_email` — HTML body, plain-text body, CC, BCC, from, reply-to, attachments (from ctx file references), mailer_method for custom mailer gets passed keyword args from ctx.
- `notify` — implement Slack (Slack Web API via HTTP), SMS (Twilio via HTTP), push notifications (FCM via HTTP). Each channel routed through `HttpRequestBuilder`. Multi-channel fallback order.

### 5.5 process/caching (4 generators)

Target: `Rails.cache` API parity.

- `cache_read` — rescue on backend error (R2); TTL validation.
- `cache_write` — actions: `write`, `write_if_absent` (new), `delete`; source variable required for write.
- `cache_fetch` — fallback can be an expression (via `OperandConverter`) or a named compute reference.
- `cache_delete` — exact key + pattern (via `delete_matched`); backend-support probe.

### 5.6 process/concurrency (2 generators)

- `acquire_lock` — add `acquireTimeout` for advisory (currently blocks indefinitely); holder identity for Redis locks; exponential backoff on retry; deadlock rescue.
- `release_lock` — mirror acquire_lock's lock_type (advisory / pessimistic / redis); validate lock-was-held via stored token.

### 5.7 process/file_operations (7 generators)

- `download_file` — `timeoutSeconds`; redirect limit; SSL verification; write to ctx or to temp file.
- `upload_file` — Active Storage attach; validate attachment service present; rescue on attach failure.
- `parse_csv`, `generate_csv` — character encoding config; delimiter validation; quote char; nested-object flattening.
- `compress_files`, `decompress_files` — `Zip` gem presence check (generate defined?-guard); compression level; path traversal protection on decompress.
- `generate_file` — PDF and Excel: generate defined?-guards for `PdfGenerator`, `ExcelGenerator`; skip generation with clear error if class missing.

### 5.8 process/human_workflow (4 generators)

Target: Trailblazer-style signal_wait pattern + persistence.

All four generators persist a request record (in a new `workflow_requests` conceptual entity — we generate code that writes to `Rails.cache` keyed on a workflow_id for now, aligned with `signal_wait`) and integrate with signal_wait for resume semantics.

- `approval_gate` — persist request; implement `majority` mode (count-based threshold); notify approvers via `notify` invocation; set up `ctx[:_signal_wait]` so the orchestrator can pair with a signal_wait.
- `assign_task` — persist task to cache; notify assignee; `waitForCompletion` sets up signal_wait.
- `escalation_generator` — schedule an escalation signal; increment escalation_count from existing ctx state.
- `user_input_request` — persist form fields; signal_wait for submission.

### 5.9 process/realtime (2 generators)

- `broadcast` — Turbo Streams branch validates action against enum; Action Cable branch validates channel class exists at runtime; rescue on publish.
- `publish_event` — validate event name format; serialize payload with `OperandConverter`.

### 5.10 process/resilience (4 generators)

Target: retryable / circuit-breaker-ruby gem parity; fix existing bugs.

- `rate_limiter` — fix off-by-one in `remaining`; replace busy-loop wait with `sleep(backoff)`; introduce jitter.
- `retry_with_backoff` — body currently empty with dead `break` — replace with real retry loop; accept `retryableErrors` list.
- `circuit_breaker` — fix half-open race via advisory lock or Redis SETNX; jitter on reset; configurable failure-count window.
- `idempotency_check` — cache result on success; `skip` action writes previously-stored result back to ctx.

### 5.11 process/response (2 generators)

- `render_response` — fix flash syntax bug in `element_types/process/response/render_response_generator.rb` (generated `if` branch has no `else` clause); HTML format renders template; headers support.
- `redirect_response` — validate URL format; actually invoke `CGI.escape` on query params (currently emitted as a string literal, not a method call) in `element_types/process/response/redirect_response_generator.rb`; support `flash` for redirects.

### 5.12 process/scheduling_time (3 generators)

- `business_hours_check` — fix `Time.parse(_time)` syntax; IANA timezone validation; DST-aware boundary check; per-day schedule map parsing.
- `deadline_check` — deadline accepts ISO8601 string or Time; reference time parsing rescued.
- `timezone_convert` — validate IANA identifier; `in_time_zone` path.

### 5.13 process/security (9 generators)

Target: Rails `MessageEncryptor` / `JWT` / `OpenSSL` / `bcrypt` / Pundit.

- `authenticate` — password uses `authenticate` method (check via `respond_to?`); token uses constant-time compare; JWT validates signature + exp + iss.
- `authorize` — role supports symbol or string; policy class constant-checked at generate-time (else generate a hint comment); custom expression via `OperandConverter`.
- `encrypt_data` / `decrypt_data` — secret key from Rails credentials via `Rails.application.credentials.dig(...)`; algorithm validation against OpenSSL cipher list; rescue on decrypt.
- `generate_token` — SecureRandom types (hex, base58, urlsafe_base64); JWT expiry accepts duration or absolute time.
- `hash_data` — bcrypt cost validated 4..31; salt format; Argon2 alternative (if gem present).
- `mask_data` — bounds-checked slicing; Unicode-aware; email/phone patterns tested against edge cases.
- `sanitize_input` — allowedTags via schema; HTML sanitizer reference via `Rails::Html::Sanitizer`.
- `verify_token` — JWT decode with rescue; algorithm list validated against `JWT.algorithms`; nested claim paths via `OperandConverter`.

### 5.14 process/service_invocation (1 generator)

- `invoke_service` — constant-check the service class in generated code; rescue service failure with R2; differentiate `ClassName.call(...)` vs `ClassName.new(...).perform(...)` via explicit config.

### 5.15 process/utility (8 generators)

- `ai_inference` — timeout; streaming support (accumulate chunks); validate model name against allow-list; safe prompt templating via `gsub` with hash (no regex injection).
- `audit_log` — persist to `AuditLog` model if present else fall back to logger; metadata through `OperandConverter`.
- `template_render` — Liquid via `Liquid::Template.parse` with registered filters allowlist; ERB dropped in favor of safe alternative (use Liquid or explicit comment-only mode).
- `i18n_translate` — locale from ctx evaluated; fallback chain; interpolation respects target type.
- `currency_convert` — rates from config (named rates var) or external provider (via `HttpRequestBuilder`); banker's rounding option.
- `geolocation_lookup` — defined?-guards for `MaxMindDB`; Haversine precision bump; target key default when missing.
- `barcode_generate`, `qr_code_generate` — defined?-guards for `Barby`, `RQRCode`; output to ctx as base64 or file reference; error_correction validated.

### 5.16 process/validation (2 generators)

- `build_contract` — configurable contract class (not hardcoded `EntityEntryContract`); cache per-class.
- `validate_contract` — resolve `ActivitySteps::DetectAndRouteParams` and siblings via `defined?` guard or move to an explicit dependency list; permission_check integrated into main validation path (both must pass, not either).

### 5.17 process/background (2 generators)

- `enqueue_job` — validate job class via `defined?`; perform_later vs perform_now explicit config.
- `schedule_job` — cron string validated via `Fugit::Cron.parse`; clock skew note; missing-schedule default.

## 6. Implementation Strategy

### 6.1 Shipping Order

1. **Cross-cutting foundation (no generator rewrites yet).**
   - Add `Shared::CtxReader`, `Shared::ErrorWrapper`, `Shared::ConfigFieldReader`, `Shared::SchemaReader`.
   - Extend `BaseGenerator` with the new mixins and `wrap_with_error_strategy` hook.

   - Update `BaseGenerator` spec + shared example spec.

Each sub-batch ships independently.**
4. **process/model_operations (17 files, split into two sub-batches: 4a read-path — find/query/count/check_existence/aggregate/pluck/batch — 7; 4b write-path — new/save/update/destroy/upsert/clone/bulk_import/soft_delete/transition_state/raw_sql — 10).**
5. **process/security (9 files).**
6. **process/communication (4 files).**
7. **process/caching (4 files).**
8. **process/concurrency (2 files).**
9. **process/file_operations (7 files).**
10. **process/human_workflow (4 files).**
11. **process/realtime (2 files).**

16. **process/utility (8 files).**

Each numbered batch is a reviewable unit. Within a batch, each generator is a self-contained change touching: `<name>_generator.rb`, `<name>_generator_spec.rb`, and the corresponding `<category>_actions.js` configSchema entry.

### 6.2 Per-Generator Workstream (Template)

For every generator, the work produces these deliverables in this order:

1. **Read the generator and its spec + its JS action_config entry.**
2. **Diff against the parity rubric (§5) for its category.** List missing config fields, missing code branches, bugs.
3. **Update `validate_config`** to accept/reject the full set of config field values.
4. **Update `generate_body`** to emit a branch for every accepted value; apply R1–R5.
5. **Update the rspec** to add a case per new branch; invoke the `"covers all configured branches"` shared example.
6. **Update `configSchema`** in the corresponding JS file.
7. **Run the spec**. Fix failures.

### 6.3 Diff Policy: Per-Generator Blocks

Producing a full per-generator spec block for all 116 generators here would double the length of this document without adding implementation value — the audit in §3/§8 plus the rubric in §5 is sufficient to drive the plan. **The per-generator blocks are produced inline during implementation, in the plan (not this spec).** This spec defines the frame; the implementation plan (produced by `writing-plans`) enumerates the 116 per-generator diffs.

### 6.4 Backward Compatibility

Per project rule in AGENTS.md: **do not take backward compatibility into consideration.** This means:
- Config field renames (R5) are propagated across all three layers in one change. Existing stored element JSON that uses old names is **not** supported. If we need migration, a separate ticket handles it.
- Generator classes whose registered names don't match the new canonical naming are renamed directly.
- No `deprecated_alias` config keys.

### 6.5 Testing Strategy

**Three levels, layered:**

- **Unit (extended existing specs).** Each `<name>_generator_spec.rb` gains one case per new config branch. Golden-string assertions are preferred (`expect(generated).to include("...")`) — full-string matching is too brittle.
- **Shared example.** `"covers all configured branches"` iterates every enum value in `configSchema.options` and asserts non-stub output. The shared example depends on `Shared::SchemaReader` to load the JS schema via a JSON export or a parallel Ruby mirror (we generate a Ruby literal from the JS at build time in `spec/support/config_schemas.rb`).
- **Integration smoke (per-category).** One per category: a minimal flowchart element representing a richest-config invocation, run through `SourceAssembler`, `eval`'d against a synthetic ctx with RSpec. Catches "Ruby doesn't parse" regressions.

**Pre-existing test failures (from memory):**
- 3 CSS component specs (unrelated, leave alone)
- 4 `query_count_branching_spec` (calls `generate` instead of `generate_body` — fix opportunistically when we touch `decision_generator`)

### 6.6 JS Schema Mirror for Specs

To avoid reading JS from Ruby at spec time, we generate a static Ruby mirror:
- `spec/support/config_schemas.rb` — a Ruby hash literal generated by a small rake task (`rake config_schemas:mirror`) that parses the JS files and emits `CONFIG_SCHEMAS = { "cache_write" => [ { key: "cacheKey", type: :text, ... } ] }`.
- `Shared::SchemaReader` reads from this mirror in test env.
- The mirror file is checked into git; CI job `rake config_schemas:check` regenerates and diffs to catch drift.

### 6.7 Telemetry

No new telemetry. Generated code writes to `ctx[:_last_error]` (already a convention in saga) — that's the extent of observability.

### 6.8 Rollout

No feature flags. Changes are merged category-by-category. Each category merge is a ship-able, user-visible improvement (the property editor reflects the new fields; existing flowcharts continue to work so long as their stored config is a subset of the new schema).

## 7. Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Scope is enormous; 116 generators × 3 layers × rspec | Timeline slip | Category-by-category shipping; each category is reviewable in isolation; no need to finish all 18 batches to get value. |
| R5 rename breaks existing flowcharts stored in DB | Data-visible regression | Per AGENTS.md rule, no back-compat. Data migration is out of scope — treat as brand-new. If this is unacceptable operationally, a one-shot rename migration is an isolated follow-up ticket. |
| JS ↔ Ruby schema drift | Stale UI fields that the generator ignores | `rake config_schemas:check` CI job diffs JS against Ruby mirror. |
| `Shared::SchemaReader` is complex to build | Foundation step blocks everything | Ruby mirror is a simple Ruby hash literal; writing the rake task to read JS via regex is ~50 LoC. If JS parsing is brittle, fallback is manual Ruby mirror maintained alongside JS. |
| External-gem `defined?`-guards add noise to generated code | Readability hit | Acceptable; better than runtime `NameError`. |
| R2 `errorStrategy` field added to every generator = schema bloat | UI noise | Field is collapsed into an "Advanced" section in the property popup (existing Advanced tab convention already present per memory). Default is `continue`, so most users never see it. |
| Rubric drift during implementation (§5 evolves as we learn) | Inconsistency across categories | Spec is source-of-truth; updates to §5 are made explicit as amendments appended to this doc, not silent changes. |
| Pre-existing test failures (4 query_count_branching, 3 CSS) | Red test suite | Explicitly out-of-scope; categorized as known baseline; CI gates only on new-file tests passing. |

## 9. Acceptance Criteria

A generator is "done" when:

1. Its `configSchema` in JS declares every field it reads.
2. Its `validate_config` rejects malformed or unknown values for every enum/required field.
3. Its `generate_body` emits a code branch for every accepted enum value; no stub fall-through.
4. Generated code is nil-safe (R1), rescue-wrapped where applicable (R2), timeout-bounded where applicable (R3), routes through shared helpers where applicable (R4), and uses canonical variable names (R5).
5. Its rspec covers every branch and passes the `"covers all configured branches"` shared example.
6. A minimal end-to-end smoke test for its category evaluates its generated Ruby without parse or NameError.

A batch is "done" when every generator in that category meets the per-generator criteria and all existing generator specs still pass.

The whole project is "done" when all 116 generators meet per-generator criteria, the three-layer invariant (§4.1) holds across the codebase, and the CI schema-drift check passes.
