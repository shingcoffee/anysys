## 开始前

需要启用支付模块。以管理员身份登录，打开**设置 → 收款服务商**。准备好服务商账户、所需支付产品审批和目标环境的凭据。模块、服务商或已连接的结账流程不可用时，请联系支持团队。

本指南介绍向客户或会员收取的款项。Anysys 服务订阅及其账单在[订阅与账单](billing)中单独管理。

## 操作步骤

### 配置收款服务商

1. 打开**设置 → 收款服务商**，查看可用服务商卡片，在目标服务商上点击**配置 →**。
2. 选择**测试**或**正式**。两者是分别保存的账户，不会自动复制凭据。请与支持团队确认本工作区结账实际使用的环境。
3. 在**连接信息**中，将未设置的**商户账户标识**改为服务商要求的账户或应用标识。同一服务商下，该标识须在各组织之间唯一。
4. 按下方说明填齐服务商凭据，并从可选项中选择**默认货币**。未获支持团队提供的专用地址时，将**通知 URL 覆盖**留空，使用默认通知地址。
5. 点击**保存更改**，修正表单错误。保存成功后会返回服务商列表；重新打开相同服务商及环境，核对已保存的标识和凭据状态。凭据留空会保留已有值，因此空白或遮蔽输入框不代表已存凭据被清除。

![已停用且未配置的测试环境收款服务商，凭据为空，并显示保存更改与测试已保存的连接控件。](/help/docs/screenshots/zh-CN/payment-settings.png "保存连接信息与测试已保存的连接是两个步骤；测试新值前请先保存。")

### 准备对应服务商的字段

仅使用本组织已开通的服务商，并请支持团队协助核对通知配置。

- **支付宝：**将应用 App ID 填入**商户账户标识**。提供 RSA2 公钥模式的**商户私钥（PEM）**和**支付宝平台公钥**，不能用证书模式文件替代。应用须获准使用所需支付流程。
- **微信支付：**将商户号填入**商户账户标识**，填写**应用 ID（公众号／小程序）**、32 字符的 **APIv3 密钥**、**商户私钥（PEM）**、**微信支付平台公钥**及**商户证书序列号**。在商户平台核对 Native、H5 或 JSAPI 产品权限、域名／目录登记和退款通知配置。
- **Stripe：**填写同一测试或正式账户配置中的**私密密钥**、**可发布密钥**和 **Webhook 签名密钥**，使用唯一的商户路由标识。请支持团队核对签名通知地址及事件选择；测试与正式环境的 Webhook 密钥不同。
- **PayPal：**填写同一 Sandbox 或 Live REST 应用的**客户端 ID**、**客户端密钥**和 **Webhook ID**，并使用唯一的商户路由标识。与支持团队登记该应用的 Webhook，核查真实付款及退款通知。

:::note
应用中的**测试**账户对应其沙箱记录，不会自动选择服务商沙箱。当前支付宝和微信支付适配器即使使用测试账户，也调用服务商的常规接口。Stripe 需匹配测试／正式密钥；PayPal 按账户环境使用 Sandbox／Live 接口。付款前请确认服务商实际环境。
:::

### 测试已保存的连接

:::note
当前支付宝和微信支付连接检查不联系服务商，只返回假定结果。即使显示**已保存的连接验证成功**，也不能证明结账、退款或签名通知可用。
:::

1. 重新打开已保存的服务商及环境，点击**测试已保存的连接**。测试读取已保存值，不读取尚未保存的输入；服务商停用时也可测试。
2. 阅读结果。失败时，修正账户、环境或凭据，保存后再测。测试不会自动启用服务商。

### 启用服务商并验证结账

1. 返回服务商列表，启用前先核对卡片显示的**环境**。开关立即保存，仅作用于卡片所示账户，不会启用所有环境。卡片环境与刚配置的环境不一致时，请支持团队安排所需账户的启用。页面提供**设为默认**时，该独立设置也立即保存，且要求服务商已配置并符合使用条件。
2. 打开本组织已连接的结账流程，使用目标服务商及币种完成约定交易。这是真实付款，请使用正确的服务商测试配置或经批准的正式金额。
3. 对照结果页、服务商记录及**模块 → 支付 → 交易**中的编号、金额和状态。正式依赖此配置前，请支持团队验证签名通知，并按需核查退款或保存卡片流程。
4. 符合条件且已登录本组织的会员，可在开始结账前，在 Stripe 服务商选择表单中勾选**保存此卡以便日后支付**。此项默认不勾选；其他服务商表单不会提交 Stripe 的保存授权，后续安全付款组件也不会再次提供保存卡片选项。

### 核对付款

1. 打开**支付**，或进入**模块 → 支付 → 交易**。
2. 找到订单编号，将服务商、金额、币种和状态与客户反馈核对。点击编号或**查看**打开详情。
3. 根据已配置的服务商和设备，结账可能展示二维码、跳转支付应用，或提供安全支付表单。请引导客户使用已连接的结账流程，不要在支持消息中索取支付资料。
4. 结果待确认时，先再次核查交易，再决定是否让客户重新付款。以服务商确认的结果为依据；记录不一致时，请联系支持团队。

### 退还已收款交易

1. 找到**成功**的交易，选择**退款**。
2. 核对订单编号和原金额。按显示的币种填写大于零的退款金额，并注明原因。例如，需要部分退款时，可从已收款 `25.00` 中退还 `10.00`。
3. 点击一次**发起退款**并阅读结果。处理中提示表示退款尚未完成。
4. 再次发起退款前，请核对服务商结果。已完成和处理中的退款总额不得超过原收款，即使表单显示的最高金额仍为原金额。

### 管理定期付款

1. 打开**模块 → 支付 → 订阅**，选择**新建订阅**。
2. 选择可用的已保存付款方式。例如，填写套餐名称 `Monthly membership`、金额 `25.00`、目标币种和每月扣款周期，点击**创建订阅**。会员需先有已激活、确认成功的保存卡片；是否支持定期扣款取决于可用服务商。
3. 打开订阅查看状态及下次扣款时间。需要结束定期付款安排时，使用取消操作，并确认结果状态。
4. 在**对账**中查看可用结算文件并下载。在**争议**中查看已记录的付款争议；后续处理请联系支持团队或服务商。

## 预期结果

交易和订阅列表显示最近 100 条记录。付款成功不等于退款已完成。会员只能使用自己账户中的支付服务、已保存卡片和订阅，前提是会员中心已开放相关服务。

## 常见问题

- **服务商列表为空：**请支持团队检查模块及服务商是否已开通。
- **结账时没有付款方式：**核对启用账户、商户标识、全部已存凭据、币种和结账环境。仅有连接测试提示不能证明已就绪。
- **新凭据似乎未生效：**先保存，重新打开相同环境，再测试已保存的连接。不要在支持消息中粘贴凭据。
- **列表显示的环境不正确：**每张卡片代表一个账户，优先显示已启用账户，否则通常显示测试账户。不要以为启用此卡片会更改正式账户；请告知支持团队需要启用哪个环境。
- **退款被拒绝：**确认款项已收取、金额大于零，并核对剩余可退款金额。
- **没有可用于订阅的保存卡片：**请会员在自己的账户中完成卡片设置。
- **缺少结算数据或较早交易：**向支持团队提供订单编号、日期和服务商。
